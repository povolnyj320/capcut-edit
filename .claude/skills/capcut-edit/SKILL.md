# /capcut-edit

Claude never clicks around in CapCut. It writes the timeline into the project's JSON, the creator opens it, tweaks and exports, and Claude learns from the tweaks. The idea comes from Matt Loui's "Automate Your CapCut Editing With Claude" (Oct 2026). Motion graphics come from HyperFrames (read the `hyperframes` skill if it's installed, or `npx hyperframes --help`).

**Style and rules live in `edit-style.md` at the repo root. Read it before every edit.** Hook, length, CTA, zoom, captions, B-roll, SFX and music all come from there. If it still has blanks, ask the creator to fill them before the first build.

**Fact-check the script before cutting it.** Check each claim the creator makes on camera against what you can verify. Tell them about any claim that's wrong before building, not after. Captions never sharpen a claim ("most efficient" does not become "fastest").

Tools live at the repo root. Run them with the project venv:
```
PY=.venv/bin/python; CC="$PY -I capcut.py"
```
Working files (transcripts, EDLs, backups, build snapshots, B-roll thumbs) go in `~/Movies/capcut-edit-work/` (or `$CAPCUT_EDIT_WORK`), never in the repo.

## The creator's part
Tell Claude which clip(s) and what the reel is about, or ask Claude to pick from the raw clips. CapCut must be closed (Cmd+Q) while Claude writes, because it rewrites the draft when it closes; Claude may quit it with `osascript -e 'tell application "CapCut" to quit'`. Claude makes the project itself (`$CC new "<name>" --from Empty`). If the creator made one already, use theirs.

## Claude's part
1. **Project and media.** `$CC new "<name>" --from <empty project>` makes an empty project by cloning one the creator made, with fresh ids, and adds it to CapCut's list (a backup of the list is kept); `$CC inspect "<project>"` lists a project they made. Put the A-roll in `~/Movies/capcut-edit-work/<project>/media/`, because CapCut can't read a file outside `~/Movies` that the creator never opened through it: copy a single clip there, or join several clips of one script into one file (`ffmpeg -f concat -safe 0 -i list.txt -map 0:v:0 -map 0:a:0 -c copy <out>.MP4`, when the clips share settings) and transcribe the joined file. Files on a synced Desktop can be iCloud-only (`ls -lO` shows `dataless`): reading the file (`cat <f> > /dev/null`) pulls it down.
2. **Transcribe.** `$PY -I transcribe.py "<A-roll path>"`. About 30 s per minute of footage on an 8 GB Mac with CapCut closed (the 4-bit model; the full one thrashes swap). Each line of the `.txt` is `[first-last word index] start-end (+gap) text`; `?` after a word means Whisper wasn't sure.
3. **Pick the keeps.** This is the editing:
   - Several takes of a line: keep the last complete one unless an earlier one is clearly better.
   - Cut false starts, restarts, half sentences, filler-only lines and tangents, freely, to hit the length in edit-style.md.
   - First kept line is the hook; the CTA is the last. Lines can be reordered.
   - Fixes go in the reel's own copy of the words file (`~/Movies/capcut-edit-work/<project>/<name>.words.json`, set as `words` in the EDL, with `media` pointing at the A-roll in the project's media folder): capitalize the first word of a kept line that started mid-sentence, merge "80" "%" into "80%" (set the `%` word to an empty string), and correct word times.
   - Keeps are word index ranges, inclusive, in play order. Whisper word times are only a guide; the builder snaps every cut to the real silence, then fits each clip to the voice: it starts on the first sound, ends on the last word (breath noise after it is cut), lets that word ring out at most 0.03 s, and puts a 20 ms fade in and 60 ms fade out on every clip so no cut pops. No hold between sentences. Whisper can end a word early: check the last word of every clip against the loudness cache (`<work>/<clip>.db.npy`, 10 ms frames), and if sound runs on past its `e`, set `e` in the reel's words copy to where it really ends. Extending the keep to the next line is the wrong fix.
4. **Write the EDL** to `~/Movies/capcut-edit-work/<project>/edl.json` (format in README.md) and run `$CC plan <edl>`. Read the clip list top to bottom as a script: no doubled words at joins, no orphan fragments, nothing that doesn't follow. Fix and re-plan until it reads clean. Then run `$PY -I check.py ears <edl>`: it re-transcribes every clip as cut and flags any that don't say what the plan says. The plan reads clean far more often than the audio is: Whisper folds a false start and its full retake into one line with a long gap (the plan then plays the line twice), keeps "So," running into a hook's first word (set `"hard": true` on the word the clip should start on), and leaves fragments of silence as one-word clips. To fix one, re-transcribe that stretch alone with word timestamps (`mlx_whisper.transcribe(..., word_timestamps=True)`), find the real take, and correct the word times in the reel's words copy. Run `ears` again until nothing is flagged. Then pick the look (rules in edit-style.md): `key` = the words that show in the accent colour, `push` = a word in each line that gets a slow push-in besides the hook. The plan marks them as `*word*` and `push`.
5. **B-roll.** Only footage the creator shot or has cleared, from the folder edit-style.md names, so nothing trips a copyright claim. A borrowed podcast clip goes in `intro` (it opens the reel) with a "via <show>" credit on screen, not "courtesy of", which claims permission. `$CC thumbs "<folder>"` saves one frame per clip, but one frame isn't enough to place a clip: make a contact sheet (`ffmpeg -i <clip> -vf "fps=1/2,scale=150:-1,drawtext=text='%{pts\\:hms}':x=4:y=4:fontsize=16:fontcolor=yellow,tile=8x2" -frames:v 1 sheet.jpg`) and pick a `src` where the action the line names is actually happening. Place clips over the lines they show (`at_word` = the word it lands on). The builder stretches each one to end on the next cut, and starts it on the previous cut when the talking clip is under 2.5 s (`cover_max`), so no B-roll edge sits inside a clip. Pick `src` so the moment you want is still inside the stretched clip. The hook gets B-roll from 0 s (`"at": 0`), covering the whole hook clip; drop any other B-roll that sat inside the hook. Don't write opacity keyframes for dissolves; CapCut 9.5 ignores them. Anything under 720 px on its short side is skipped by the build, and 720 to 1079 px is listed as soft, so pick sharp clips. No SFX on B-roll.
6. **Motion graphics.** Read the HyperFrames skill (`hyperframes`, and its `references/overlays.md` and `motion.md`) first if it's installed. Then:
   - Plan the package against the timeline: `$CC plan` gives every clip's start; pin each graphic to the word it belongs on. Top band (180 to 400 px, above the head) for running elements, lower band (1080 to 1330 px, under the centered captions) for cards and explainers, a full-screen cutaway for the one idea that needs the whole frame.
   - Start from the kit: copy `hyperframes-kit/` to `~/Movies/capcut-edit-work/graphics/<project>/` and set `graphics_dir` in the EDL to it. It has the brand stylesheet (`assets/hp.css`), a fonts folder (the creator puts their display font there), every template (hook, tracker, card, meter, battery, name tag, week checks, graph cutaway, mini graph, comment CTA, `meter-steps`, `zone`, `split`, `checks`, `chips`, `chips5`, `status`, `myth`, `beats`, `hilo`, `wb-card`), two caption tracks and two full example EDLs. They follow the clean spec in edit-style.md: soft fades and slides, light shadows, no blur pops, slams or shakes.
   - Graphics are timed by cues, not hard-coded seconds: each template starts with `const C = /*CUES*/{...}/*END*/`. In the EDL, a graphic names its template (`html`), output `name`, start (`at_word`), end (`until_word`, or the reel's end), and `cues` as word indices (`"five": 9`; `"281e"` = the end of word 281). `out` (when it leaves) defaults to 0.3 s before its end. `$CC graphics <edl>` fills the cues from the final timeline and renders every graphic into `out/` (about 5 minutes for 16); `--only card4 captions` renders just those. Re-run it after any change to the keeps, because cuts move every word.
   - Rules the kit already follows: transparent page for overlays; fonts named in each file's own style block (HyperFrames ignores fonts named only in the linked stylesheet); starting states with `gsap.set` before the timeline, never `tl.set(..., 0)`; no `<style>` text inside CSS comments.
   - New or edited templates: `hyperframes lint <file>.html` first (only the "nested structure" warning may stay). Overlays render as ProRes 4444 MOV with alpha; an opaque cutaway takes `"format": "mp4"`; cards take `"vars": {"num": "02", "kicker": "Step 02", "name": "Warm up"}`.
   - **Whiteboard cutaways** are one template, `whiteboard.html`, played from a `"scenes"` list in its EDL entry (`"format": "mp4"`, lane -1). Scenes and icons live in `assets/wb.js`; read its comments for each scene's fields. Scene types: `icons` (1 to 3 line icons with labels, each on its own word; `link` "dash", "arrow" or "vs"; `battery` fills on `fillCue`), `hilo` (two bars), `zone` (0 to 100% bar with a band), `bignum`, `week` (7 days filling), `heartbeat`, `list`, `bars`, `split`, `checks`. Any scene takes `title`, `sub`, `note`, `x`/`y`; `keep: "dim"` or `"full"` keeps the scene before it up; `carry: "heart", carryTo: [x, top, scale]` moves that icon from the scene before into this one. Text: `*word*` is the accent colour, `\n` breaks the line. Times: `"at"` and any key ending in `cue` take a word index, `"281e"` or `"start"`. An arrow link claims one thing causes the other; use it only when the script says so. `edl-recovery-merged.json` in the kit is the worked example. A whiteboard stays up only while something new lands on it, never more than about 1.5 s without a change; `check.py still <edl>` lists every hold over 1.5 s.
   - Captions: the HyperFrames caption track (`"html": "captions-min.html", "kind": "captions", "lane": 3`) replaces CapCut's (set `"captions": false`). White, sentence case, 1 to 3 words that fade and rise together, the `key` word static in the accent colour, nothing behind the text; groups break at commas, sentence ends, capitals and cut-out pauses; hidden under an opaque cutaway. `captions-word.html` is one word at a time (cue `"hook"` = the first word after the hook B-roll).
   - Look before using it: `$PY -I check.py frames <edl> <out.jpg> 1.0 4.5 9.0 ...` tiles the real frame (A-roll at its zoom, or B-roll) with every graphic and the captions live at each time; read the image. Check that big titles miss the head and that labels don't collide; a name or card whose reveal word is the last of its line shows for a blink, so reveal it earlier.
   - For a normal reel, show the creator the first graphic and wait for their OK before making the rest in the same style.
   - EDL: overlays in `graphics` with a `lane` (0 for a long running element, 1 for explainers, 2 for cards, 3 for captions; higher lanes draw on top). An opaque full-screen cutaway goes in `graphics` on lane -1, above the colour grade (so its colours stay true) and under the running tracker. Add an SFX on each graphic's hit.
7. **Build.** `pgrep -x CapCut` must print nothing, then `$CC build <edl>` (`--replace` rebuilds a project that already has a timeline; a backup is kept either way). The build refuses to write a draft that fails its self-check (missing materials, overlaps, clips past the end of their media). Then `check.py gaps <edl>` lists every quiet stretch over 0.15 s; one inside a line is the creator's own pause and stays, one at a cut needs a look.
8. **Report:** clip count, length, and every cut as one line each (what was said, why it went), so the creator can put anything back.
9. **Learn.** After the creator tweaks and quits CapCut, run `$CC diff "<project>"`. Turn what they changed into rules in `edit-style.md`. When `diff` shows they resized or moved a graphic, copy it into that graphic's EDL entry as `"scale"`, `"x"`, `"y"` (CapCut's own units, read from the segment's `clip` in `draft_info.json`) before any `--replace` rebuild, or the rebuild undoes it.

## Learn a style from reel links
When the creator sends TikTok or Instagram links to copy another creator's look (3 links minimum, 5 is better):
1. **Download** into `~/Movies/capcut-edit-work/references/`: `yt-dlp -o "$HOME/Movies/capcut-edit-work/references/%(uploader)s_%(id)s.%(ext)s" <links>`. Public IG reels and TikToks need no login.
2. **Read each one.** `transcribe.py` for the words and pauses. Contact sheets for the look: `ffmpeg -i <file> -vf "fps=1/3,scale=360:-1,tile=4x2" sheet_%02d.jpg`, then read the images; pull single frames at moments that matter. Cut times: `ffmpeg -i <file> -vf "scale=180:-1,select='gt(scene,0.05)',showinfo" -an -f null - 2>&1 | grep -o 'pts_time:[0-9.]*'` (merge hits under 0.2 s apart; overlays changing also count, so check against the sheets).
3. **Break down what the reels share:** average clip length and cuts per 10 s, how much pause survives a jump cut, zooms (when and how far), captions (font, size, colour, position, words per line, animation, which words pop), graphics, emojis, pop-ups and B-roll and when they land, colour, SFX and music levels, and what happens in the first 3 seconds.
4. **Show the creator** the breakdown next to their own numbers in edit-style.md and ask about anything unclear. What they want to adopt becomes rules in edit-style.md, each marked with the creator it came from. Never replace their rules without their OK.

## How the builder works (for fixing it)
- CapCut 9.x keeps the timeline in `draft_info.json` at the project root plus an identical copy in `Timelines/<id>/`; the builder writes both and updates `draft_meta_info.json`. Times are microseconds.
- Every clip, caption and audio segment is a clone of one of the creator's own, saved in `style.json` by `$CC style <project> [<project2>..]` (the first project listed wins for each piece). The colour layer is their adjustment track (a LUT effect and HSL). Run `style` again after a CapCut update if builds stop opening.
- The colour layer sits above the B-roll and below graphics and captions, so it grades the footage but leaves the graphics' colours true.
- Push-ins are `common_keyframes` on the clip: one `KFTypeScaleX` and one `KFTypeScaleY` list with a keyframe at 0 and one at the clip's end.
- Accent words are extra style runs in the caption's text content: the template's style copied per run, with the fill colour set on key words. Ranges count UTF-16 units.
- All captions in a draft share one `name` (the caption-group id). Changing it per caption makes CapCut show "THE QUICK BROWN FOX" instead of the words.
- CapCut is sandboxed: it reads `~/Movies` and files the creator opened through it, nothing else. Files it can't reach come up in a "Link media" box. So the build copies every SFX, music and B-roll file into `<work>/<project>/media/` under an ASCII-safe name and points the draft there; graphics already render into `~/Movies`. The A-roll goes in the same folder before planning (step 1), unless the creator imported it through CapCut themselves.
- Checking in CapCut: frame-stepping with the arrow keys is unreliable when the Mac is low on memory, so verify edge timing from the plan numbers and use CapCut only to confirm media loads and graphics render.
- CapCut's effect cache drops old caption templates and fonts. On first open CapCut downloads them again and fixes the paths itself. If captions still show placeholder text, quit and reopen once.
